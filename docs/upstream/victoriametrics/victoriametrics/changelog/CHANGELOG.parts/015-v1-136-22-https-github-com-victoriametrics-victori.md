## [v1.136.22](https://github.com/VictoriaMetrics/VictoriaMetrics/releases/tag/v1.136.22)

Released at 2026-10-23

**v1.136.x is a line of [LTS releases](https://docs.victoriametrics.com/victoriametrics/lts-releases/). It contains important up-to-date bugfixes for [VictoriaMetrics enterprise](https://docs.victoriametrics.com/victoriametrics/enterprise/).
All these fixes are also included in [the latest community release](https://github.com/VictoriaMetrics/VictoriaMetrics/releases/latest).
The v1.136.x line will be supported for at least 12 months since [v1.136.0](https://docs.victoriametrics.com/victoriametrics/changelog/#v11360) release**

* SECURITY: upgrade Go builder from Go1.26.9 to Go1.26.10. See [the list of issues addressed in Go1.26.10](https://github.com/golang/go/issues?q=milestone%3AGo1.26.10%20label%3ACherryPickApproved).
* SECURITY: upgrade base docker image (Alpine) from 3.24.2 to 3.24.3. See [Alpine 3.24.4 release notes](https://alpinelinux.org/posts/Alpine-3.21.9-3.22.7-3.23.7-3.24.3-released.html).

* BUGFIX: [vmsingle](https://docs.victoriametrics.com/victoriametrics/single-server-victoriametrics/) and [vmagent](https://docs.victoriametrics.com/victoriametrics/vmagent/): set `__meta_kubernetes_namespace` and the namespace metadata to the namespace of the `Endpoints` or `EndpointSlice` object in [`role: endpoints`](https://docs.victoriametrics.com/victoriametrics/sd_configs/#kubernetes_sd_configs) and `role: endpointslice` service discovery when the referenced pod lives in another namespace. Previously the namespace of the pod was used, unlike Prometheus. See [#11798](https://github.com/VictoriaMetrics/VictoriaMetrics/issues/11798). Thanks to @cestercian for contribution.
* BUGFIX: [vmui](https://docs.victoriametrics.com/victoriametrics/single-server-victoriametrics/#vmui): stop saving the automatically calculated query step in shared URLs, so opening a link recalculates the step for the selected time range and screen width. Explicitly configured steps remain fixed. See [#11638](https://github.com/VictoriaMetrics/VictoriaMetrics/issues/11638).


## [v1.136.21](https://github.com/VictoriaMetrics/VictoriaMetrics/releases/tag/v1.136.21)

Released at 2026-10-19

**v1.136.x is a line of [LTS releases](https://docs.victoriametrics.com/victoriametrics/lts-releases/). It contains important up-to-date bugfixes for [VictoriaMetrics enterprise](https://docs.victoriametrics.com/victoriametrics/enterprise/).
All these fixes are also included in [the latest community release](https://github.com/VictoriaMetrics/VictoriaMetrics/releases/latest).
The v1.136.x line will be supported for at least 12 months since [v1.136.0](https://docs.victoriametrics.com/victoriametrics/changelog/#v11360) release**

* BUGFIX: [vmagent](https://docs.victoriametrics.com/victoriametrics/vmagent/): prevent [Kafka remote write](https://docs.victoriametrics.com/victoriametrics/integrations/kafka/) getting stuck after TLS certificates are reloaded. Previously, when vmagent detected changed certificates and restarted the Kafka producer, pending sends to the old producer could hang forever and the remote write queue stopped draining until vmagent was restarted. Now such sends are retried with the new producer. See [#11737](https://github.com/VictoriaMetrics/VictoriaMetrics/issues/11737).
* BUGFIX: [vmsingle](https://docs.victoriametrics.com/victoriametrics/single-server-victoriametrics/), [vmagent](https://docs.victoriametrics.com/victoriametrics/vmagent/) and `vminsert` in [VictoriaMetrics cluster](https://docs.victoriametrics.com/victoriametrics/cluster-victoriametrics/): properly validate time series ingested via [`/api/v1/import/native`](https://docs.victoriametrics.com/victoriametrics/single-server-victoriametrics/#how-to-import-data-in-native-format). See [#11745](https://github.com/VictoriaMetrics/VictoriaMetrics/pull/11745). Thanks to @meshchellomishel for contribution.
* BUGFIX: [vmsingle](https://docs.victoriametrics.com/victoriametrics/single-server-victoriametrics/) and [vmagent](https://docs.victoriametrics.com/victoriametrics/vmagent/): reduce memory usage during for Kubernetes service discovery, when scrape configuration has many entries that matches small subset of targets. See [#11751](https://github.com/VictoriaMetrics/VictoriaMetrics/pull/11751). Thanks to @CamberLoid for contribution.


## [v1.136.20](https://github.com/VictoriaMetrics/VictoriaMetrics/releases/tag/v1.136.20)

Released at 2026-10-09

**v1.136.x is a line of [LTS releases](https://docs.victoriametrics.com/victoriametrics/lts-releases/). It contains important up-to-date bugfixes for [VictoriaMetrics enterprise](https://docs.victoriametrics.com/victoriametrics/enterprise/).
All these fixes are also included in [the latest community release](https://github.com/VictoriaMetrics/VictoriaMetrics/releases/latest).
The v1.136.x line will be supported for at least 12 months since [v1.136.0](https://docs.victoriametrics.com/victoriametrics/changelog/#v11360) release**


* SECURITY: upgrade Go builder from Go1.26.8 to Go1.26.9. See [the list of issues addressed in Go1.26.9](https://github.com/golang/go/issues?q=milestone%3AGo1.26.9%20label%3ACherryPickApproved).

* BUGFIX: all VictoriaMetrics components: correctly configure TCP keep-alive active probes. See [#11695](github.com/VictoriaMetrics/VictoriaMetrics/issues/11695).
* BUGFIX: all VictoriaMetrics components: properly match regexps that start with an alternation or a character class and continue with `.*foo.*` or `.+foo.+`, for example `(a|b).*foo.*`. Previously the leading part was ignored when matching [relabeling](https://docs.victoriametrics.com/victoriametrics/relabeling/) `regex` and `if` filters and [stream aggregation](https://docs.victoriametrics.com/victoriametrics/stream-aggregation/) `match` filters, so such rules matched more series than intended. See [#11712](https://github.com/VictoriaMetrics/VictoriaMetrics/issues/11712). Thanks to @dblackdblack for contribution.
* BUGFIX: [stream aggregation](https://docs.victoriametrics.com/victoriametrics/stream-aggregation/): properly add timeseries for [increase](https://docs.victoriametrics.com/victoriametrics/stream-aggregation/configuration/#increase), [increase_prometheus](https://docs.victoriametrics.com/victoriametrics/stream-aggregation/configuration/#increase_prometheus), [total](https://docs.victoriametrics.com/victoriametrics/stream-aggregation/configuration/#total) and [total_prometheus](https://docs.victoriametrics.com/victoriametrics/stream-aggregation/configuration/#total_prometheus) aggregation functions when `enable_windows: true` is set. See [#11707](https://github.com/VictoriaMetrics/VictoriaMetrics/issues/11707). Thanks to @Hoipang for contribution.
* BUGFIX: [vmalert](https://docs.victoriametrics.com/victoriametrics/vmalert/): keep using notifiers from the previously applied [notifier configuration file](https://docs.victoriametrics.com/victoriametrics/vmalert/#notifier-configuration-file) if the updated config fails to start, for example due to a temporary service discovery error, and retry applying it on the next reload. Previously, vmalert stopped the old notifiers before starting the new ones, so a failed reload left vmalert with no or only some notifiers, and alert notifications were silently not delivered until the file changed or vmalert restarted. See [#11645](https://github.com/VictoriaMetrics/VictoriaMetrics/pull/11645).
* BUGFIX: [vmalert](https://docs.victoriametrics.com/victoriametrics/vmalert/): copy alert labels before applying `alert_relabel_configs` from the [notifier configuration file](https://docs.victoriametrics.com/victoriametrics/vmalert/#notifier-configuration-file), preventing different alertmanagers from affecting each other's labels. See [#11676](https://github.com/VictoriaMetrics/VictoriaMetrics/issues/11676).
* BUGFIX: [vmauth](https://docs.victoriametrics.com/victoriametrics/vmauth/): fixes rare data corruption on HTTP request retries. See [#11508](https://github.com/VictoriaMetrics/VictoriaMetrics/issues/11508).
* BUGFIX: `vmselect` in [VictoriaMetrics cluster](https://docs.victoriametrics.com/victoriametrics/cluster-victoriametrics/): add missing `accountID`, `projectID` and `multiTenant` fields to `topByAvgMemoryUsage` results at `/api/v1/status/top_queries`. See [#11640](https://github.com/VictoriaMetrics/VictoriaMetrics/issues/11640).
* BUGFIX: [vmsingle](https://docs.victoriametrics.com/victoriametrics/single-server-victoriametrics/) and `vmselect` in [VictoriaMetrics cluster](https://docs.victoriametrics.com/victoriametrics/cluster-victoriametrics/): properly execute `group_left(...)` and `group_right(..)` queries when the join is then combined with another selector. See [#11490](https://github.com/VictoriaMetrics/VictoriaMetrics/issues/11490).
* BUGFIX: [vmsingle](https://docs.victoriametrics.com/victoriametrics/single-server-victoriametrics/) and `vmstorage` in [VictoriaMetrics cluster](https://docs.victoriametrics.com/victoriametrics/cluster-victoriametrics/): prevent possible crash with `cannot decompress zstd data...` panic on `darwin`, `windows`, `freebsd`, `openbsd`, `linux/arm`, `linux/ppc64le`, `linux/386`, `linux/s390x`, and `-pure` builds. The `linux/amd64` and `linux/arm64` builds are not affected. See [#11683](https://github.com/VictoriaMetrics/VictoriaMetrics/issues/11683).
* BUGFIX: [vmsingle](https://docs.victoriametrics.com/victoriametrics/single-server-victoriametrics/): properly apply `-streamAggr.enableWindows` command-line flag to [stream aggregation](https://docs.victoriametrics.com/victoriametrics/stream-aggregation/) rules. Previously, the flag was ignored by aggregation rules defined in `-streamAggr.config` and was applied only during config validation with `-dryRun` and to the standalone deduplication configured via `-streamAggr.dedupInterval`. See [#11717](https://github.com/VictoriaMetrics/VictoriaMetrics/pull/11717).
* BUGFIX: [vmui](https://docs.victoriametrics.com/victoriametrics/single-server-victoriametrics/#vmui): prevent overriding the `serverUrl`, `tenantId`, `theme`, and `isDarkTheme` settings via query parameters. See [#11485](https://github.com/VictoriaMetrics/VictoriaMetrics/pull/11485#issuecomment-5779024739).
* BUGFIX: [vmbackup](https://docs.victoriametrics.com/victoriametrics/vmbackup/) and [vmbackupmanager](https://docs.victoriametrics.com/victoriametrics/vmbackupmanager/): add `-s3SkipTaggingDirective` command-line flag for S3-compatible storage that rejects the `x-amz-tagging-directive` and `x-amz-tagging` headers. See [#11562](https://github.com/VictoriaMetrics/VictoriaMetrics/issues/11562).


## [v1.136.19](https://github.com/VictoriaMetrics/VictoriaMetrics/releases/tag/v1.136.19)

Released at 2026-09-25

**v1.136.x is a line of [LTS releases](https://docs.victoriametrics.com/victoriametrics/lts-releases/). It contains important up-to-date bugfixes for [VictoriaMetrics enterprise](https://docs.victoriametrics.com/victoriametrics/enterprise/).
All these fixes are also included in [the latest community release](https://github.com/VictoriaMetrics/VictoriaMetrics/releases/latest).
The v1.136.x line will be supported for at least 12 months since [v1.136.0](https://docs.victoriametrics.com/victoriametrics/changelog/#v11360) release**

**Update Note 1:** [vmsingle](https://docs.victoriametrics.com/victoriametrics/single-server-victoriametrics/), `vmstorage`, `vmselect` and `vminsert` in [VictoriaMetrics cluster](https://docs.victoriametrics.com/victoriametrics/cluster-victoriametrics/), and [vmagent](https://docs.victoriametrics.com/victoriametrics/vmagent/): builds without CGO (pure Go) may fail to read valid data blocks with the `window size exceeded` error. This can break queries, background merges and [native import](https://docs.victoriametrics.com/victoriametrics/single-server-victoriametrics/#how-to-import-data-in-native-format), and can make `vmsingle` and `vmstorage` crash. Blocks written by earlier releases are affected too. Affected official builds: `darwin`, `windows`, `freebsd`, `openbsd`, `linux/arm`, `linux/ppc64le`, `linux/386`, `linux/s390x`, and `-pure` builds. The `linux/amd64` and `linux/arm64` builds use CGO and are not affected. Users of affected builds should not upgrade to this release, or should roll back to [v1.136.18](https://docs.victoriametrics.com/victoriametrics/changelog/#v113618). See [#11683](https://github.com/VictoriaMetrics/VictoriaMetrics/issues/11683).

* SECURITY: `vminsert`, [vmagent](https://docs.victoriametrics.com/victoriametrics/vmagent/) and [vmsingle](https://docs.victoriametrics.com/victoriametrics/single-server-victoriametrics/): properly apply memory limits to the `zstd` encoded blocks ingested via [native import](https://docs.victoriametrics.com/victoriametrics/single-server-victoriametrics/#how-to-import-data-in-native-format). This prevents excessive memory allocation during ingestion when handling maliciously crafted requests. See [GHSA-8g4f-32hw-vqf8](https://github.com/VictoriaMetrics/VictoriaMetrics/security/advisories/GHSA-8g4f-32hw-vqf8).
* SECURITY: upgrade base docker image (Alpine) from 3.24.1 to 3.24.2. See [Alpine 3.24.2 release notes](https://www.alpinelinux.org/posts/Alpine-3.24.2-released.html).

* BUGFIX: [stream aggregation](https://docs.victoriametrics.com/victoriametrics/stream-aggregation/): serially push samples to [stream aggregation](https://docs.victoriametrics.com/victoriametrics/stream-aggregation/) jobs. This helps reduce CPU overhead. [11f488d8ff](https://github.com/VictoriaMetrics/VictoriaMetrics/commit/11f488d8ff) introduced parallel processing for this stage, which introduced extra CPU overhead while only providing negligible sample lag reduction. See [#9878](https://github.com/VictoriaMetrics/VictoriaMetrics/issues/9878#issuecomment-5692311649).
* BUGFIX: [vmagent](https://docs.victoriametrics.com/victoriametrics/vmagent/): add missing `X-Influxdb-Version` HTTP header to [influxdb](https://docs.victoriametrics.com/victoriametrics/integrations/influxdb/) API responses. See [#11570](https://github.com/VictoriaMetrics/VictoriaMetrics/issues/11570).
* BUGFIX: [vmagent](https://docs.victoriametrics.com/victoriametrics/vmagent/) and [vmsingle](https://docs.victoriametrics.com/victoriametrics/single-server-victoriametrics/): properly discover `*_sd_config` targets. Previously scrape targets were preserved until the process restart if `*_sd_config` returned an empty targets response. See [#11550](https://github.com/VictoriaMetrics/VictoriaMetrics/issues/11550) for details. Thanks to @evkuzin for contribution.
* BUGFIX: [vmagent](https://docs.victoriametrics.com/victoriametrics/vmagent/): properly reload SSL certificate for [kafka producer and consumer](https://docs.victoriametrics.com/victoriametrics/integrations/kafka/). See [#11577](https://github.com/VictoriaMetrics/VictoriaMetrics/issues/11577).
* BUGFIX: [vmsingle](https://docs.victoriametrics.com/victoriametrics/single-server-victoriametrics/), `vmselect` in [VictoriaMetrics cluster](https://docs.victoriametrics.com/victoriametrics/cluster-victoriametrics/): prevent the process from crashing when [limit_offset](https://docs.victoriametrics.com/victoriametrics/metricsql/#limit_offset) is called with a negative `limit` or `offset` argument. See [#11561](https://github.com/VictoriaMetrics/VictoriaMetrics/pull/11561). Thanks to @theoneLee for contribution. 
* BUGFIX: [vmalert](https://docs.victoriametrics.com/victoriametrics/vmalert/): properly reload `alert_relabel_configs` from the [notifier configuration file](https://docs.victoriametrics.com/victoriametrics/vmalert/#notifier-configuration-file). Previously, this config was applied only at startup and was not updated on config reload. See [#11635](https://github.com/VictoriaMetrics/VictoriaMetrics/issues/11635).
* BUGFIX: [vmauth](https://docs.victoriametrics.com/victoriametrics/vmauth/): respect the `-enableTCP6` flag when discovering backend IPs via [`discover_backend_ips`](https://docs.victoriametrics.com/victoriametrics/vmauth/#discovering-backend-ips) or `-discoverBackendIPs`. Previously, discovery included IPv6 addresses even when IPv6 support was disabled. See [#11470](https://github.com/VictoriaMetrics/VictoriaMetrics/issues/11470).
* BUGFIX: [vmui](https://docs.victoriametrics.com/victoriametrics/single-server-victoriametrics/#vmui): fix synchronization of the custom query step with URL changes on the predefined dashboards page. See [#11137](https://github.com/VictoriaMetrics/VictoriaMetrics/issues/11137#issuecomment-5396835285).
* BUGFIX: `vmselect`, `vminsert`, [vmagent](https://docs.victoriametrics.com/victoriametrics/vmagent/) and [vmsingle](https://docs.victoriametrics.com/victoriametrics/single-server-victoriametrics/): ignore empty `extra_label`, `extra_filters` and `extra_filters[]` query args instead of returning an error. This allows dropping client-provided values for these query args via `url_prefix` in vmauth as described in the [security](https://docs.victoriametrics.com/victoriametrics/vmauth/#security) docs. See [#11618](https://github.com/VictoriaMetrics/VictoriaMetrics/issues/11618).
* BUGFIX: [vmsingle](https://docs.victoriametrics.com/victoriametrics/single-server-victoriametrics/) and `vmselect` in [VictoriaMetrics cluster](https://docs.victoriametrics.com/victoriametrics/cluster-victoriametrics/): slightly reduce CPU usage during concurrent queries execution. See [#11569](https://github.com/VictoriaMetrics/VictoriaMetrics/issues/11569).
