# Platform brain: rules for Claude inside this repo

This repo is the shared memory of four platform teams. People and future Claude sessions act on what
you write here, often during incidents. A wrong or over-confident page is worse than a missing one.

## Layout

| Path | What |
|---|---|
| `commons/` | Shared: OpenShift, Argo CD, Helm, GitLab, storage, networking, monitoring, Python |
| `team1-mongodb-cassandra/` | MongoDB, MCK, Ops Manager, Cassandra, K8ssandra |
| `team2-elastic/`, `team3-redis/`, `team4-placeholder/` | Each team's own technologies |
| `<team>/knowledge/` | How things work here, gotchas, root causes, lessons, wrong assumptions |
| `<team>/runbooks/` | Step-by-step procedures |
| `<team>/decisions/` | Decisions and why (`README.md` lists the ones still to write) |
| `inbox/` | Unsure saves waiting for a person to review |
| `templates/` | `knowledge`, `overview`, `runbook`, `decision` |
| `scripts/` | `brain.py` (validate, index, rules, stale) and `brain_save.py` (push to main) |
| `plugin/` | The Claude Code plugin: hooks and the `lookup` / `learn` / `curate` skills |
| `docs/` | `FRONTMATTER.md` (header rules), `DESIGN.md` (how and why), `ADMIN.md` (maintenance) |
| `docs/upstream/` | Offline vendor docs, generated by `scripts/sync_upstream_docs.py`. Never edit by hand; catalog: `commons/knowledge/upstream-docs.md` |
| `tests/test_flow.sh` | End-to-end test; run it after changing `scripts/` or `plugin/scripts/` |
| `INDEX.md`, `<team>/INDEX.md` | Generated at session start. Never edit, never commit |

Version questions: `commons/knowledge/platform-versions.md` first.

## Saving: straight to main, after the engineer says yes

- No branches, no merge requests. Every change, tooling included, goes through:
  `bash scripts/run.sh brain_save.py -m "brain(<team>): <what was learned>" <file> [<file> ...]`
  It checks the pages, commits only those files, rebases on `origin/main` and pushes, retrying if
  someone pushed first.
- Run it only after the engineer said yes to that exact change.
- Never force-push and never commit with raw git: `brain_save.py` runs the checks.
- On a conflict (exit code 2), follow the printed steps and keep both people's facts.
- Commit messages: `brain(<team>|curate|meta): <what changed>`.

## Writing rules

- **Search first:** `grep -rilE '<terms>' --include='*.md' --exclude-dir=upstream .` Update an existing page rather than
  adding a near-duplicate: set `last_verified` to today and add a `## History` line.
- **Start from a template.** Header fields: `title`, `type`, `tags`, `applies_to`, `confidence`
  (decisions use `status`), `last_verified`, `owners`, `source`, and an optional `rule`.
  Exact rules: `docs/FRONTMATTER.md`.
- **A version changed?** Update `commons/knowledge/platform-versions.md` and the component's page in
  the same save.
- **`confidence`:** `verified` = confirmed by the owning team or tested working; `observed` = seen
  once, or read in docs or code; `hypothesis` = believed, not confirmed. Never raise it without evidence.
- **`rule`:** one line, `<situation> → <what to do>`. Every session sees it at start, so add one only
  for a clear, reusable rule.
- **Scope everything:** versions and environments in `applies_to` (`ocp-4.18`, `mongo-8.0`, `mck-1.10`);
  version ranges in prose ("since 6.0", "up to 5.0"), never "the current version".
- **Gaps are `[UNKNOWN]`.** Never fill them with guesses.
- **No secrets:** passwords, tokens, keys, certificates, connection strings with credentials,
  customer data become `<REDACTED>`. `brain.py validate` catches common patterns, not everything,
  so check yourself. `brain:allow-secret` at the end of a line silences a false positive.
- Cite related pages by path in backticks, e.g. `commons/knowledge/gitops-pipeline.md`.

## Checks

```bash
bash scripts/run.sh brain.py validate            # every page
bash scripts/run.sh brain.py stale --days 180    # pages nobody re-checked lately
```

After changing hooks or skills in `plugin/`, bump `version` in `plugin/.claude-plugin/plugin.json`.
